# PART B: Phase 2 Spec (Platform with Accounts) — NOT for Round 1

**Status:** Do not start until the client confirms scope, and quote it separately. Round 1 ships only the calculator.

## B1. Stack
Next.js (same project) + Supabase (Postgres, Auth, Row Level Security, Storage). Scoring still runs from the same `scoring.ts` and `model.json`.

## B2. Roles and permissions
Four roles. The methodology table omits Patient, so it is added here.

| Feature | Admin | Doctor | Researcher | Patient |
|---|---|---|---|---|
| Dashboard | Y | Y | N | N |
| Create & review case | Y | Y | N | N |
| Patient profile | Y | Y | N | N |
| Research & insights | Y | N | Y | N |
| System management | Y | N | N | N |
| My Health | N | N | N | Y (own data only) |

Enforce with Row Level Security, not only by hiding buttons.

## B3. Modules

**Dashboard (Doctor, Admin)**
- Search patient by name, national ID or patient ID.
- Latest patient files, with filtering.
- Recently opened files (one-click access).
- High-risk alerts: cases whose latest level is "High".

**Create & review (Doctor, Admin)**
- New patient file: full name, national ID, gender, date of birth, phone, medical history summary.
- Temporary file: label or name, gender, age, medical notes. Not linked to a national ID.
- After creating a file, the doctor enters symptoms and labs, and the score is computed and saved as a visit.

**Patient profile (Doctor, Admin)**
- Overview with editable personal info, and "add clinical visit".
- Medical history summary.
- Current symptoms from the last visit.
- Latest investigations and tests.
- Recorded diagnosis (entered by the doctor, never generated by the tool).
- Score history with comparison between visits.

**Research & insights (Researcher, Admin)**
- Add new cases by Excel upload. Build Excel/CSV first. PDF parsing is unreliable, so treat it as a later add-on.
- Imported cases go to a **review queue** and never change the live model automatically.
- Patient case page: view the data needed for research.
- The site does not retrain the model. Hazem regenerates `model.json` from approved cases.

**System management (Admin)**
- User accounts and roles: list, create, update role, delete.
- Medical lists: investigations, symptoms (name + points), diagnoses, specialties.
- Scoring and lab ranges: edit normal ranges and points. **Decision needed:** `model.json` is the source of truth. Recommended: admin edits create a new draft model version that Hazem approves, instead of editing live numbers.
- Review changes: the latest 200 changes (who, what, when).
- Backup and restore: use Supabase backups. Do not build a custom backup system.

**My Health (Patient)**
- Patient sees only their own scans and test results. Needs file storage with private access. Confirm this is wanted before building.

## B4. Data model (starting point)
```sql
profiles(id, role, email)
patients(id, national_id, full_name, gender, dob, phone, history_summary, created_by)
temp_patients(id, label, gender, age, notes, created_by)
visits(id, patient_id, doctor_id, date, symptoms jsonb, labs jsonb, total, probability, level, model_version)
imported_cases(id, uploaded_by, data jsonb, status)   -- pending / approved / rejected
audit_log(id, user_id, action, target, at)
```
Store `model_version` on every visit so old scores stay explainable after the model changes.

## B5. Security and legal (required)
- **Demo data only: fake patients and fake IDs.** Real national IDs plus medical history are sensitive health data under Egypt's data protection law. A student project must not store real ones.
- Egyptian national ID = 14 digits; validate the format.
- National IDs never appear in URLs, logs or analytics. Use internal UUIDs in routes.
- Row Level Security on every table. Doctors see only the patients they are allowed to see. Patients see only their own rows.
- Log every read and write of patient records to `audit_log`.
- Encrypt data in transit (HTTPS). Use Supabase defaults for storage encryption.
- Do not claim HIPAA, GDPR or any certification.

## B6. Milestones (after round 1)
1. Auth + roles + RLS, with tests that a doctor cannot read another role's data.
2. Patient files + visits + score saving.
3. Dashboard (search, recent, high-risk).
4. Research import (Excel) + review queue.
5. Admin area + audit log.
6. My Health (only if confirmed).

## B7. Do NOT (Phase 2)
- Store real patient data.
- Let imports or admin edits change live scoring without approval.
- Use "AI" or "diagnosis" wording for the output.
- Add messaging or a chatbot.
